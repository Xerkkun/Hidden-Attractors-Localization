# Common trajectory and analysis-result contract

HAFO analyses may consume trajectories generated by integer flows, integer
maps, fractional continuous systems, future fractional-difference systems, or
external sampled data. The same array can have a different scientific meaning
when its sampling, projection, derivative, order, lower terminal, prehistory,
or memory policy changes. The experimental `TrajectoryInput`, `PrehistorySpec`,
and `AnalysisResult` contracts retain those distinctions.

The contract is additive. Existing numerical functions that accept NumPy
arrays continue to do so, and existing specialized result classes do not have
to inherit from `AnalysisResult`.

## `PrehistorySpec`

`PrehistorySpec.kind` is always explicit:

| Kind | Meaning |
|---|---|
| `not_applicable` | Integer dynamics or generic sampled data have no hereditary initial history. |
| `point_initial_value` | Only the initial value at the lower terminal is part of the declared numerical contract. |
| `sampled` | A finite, strictly ordered history table is supplied. |
| `analytic_reference` | History is identified by an importable function or declared formula reference over a coverage interval. |
| `unknown` | The missing provenance is recorded rather than silently treated as zero or as a point initial condition. |

Describing a sampled or analytic prehistory does **not** make an existing
solver consume it. In particular, solvers that currently reject a lower
terminal before the simulated initial time continue to reject it.

```python
from hidden_attractors.analysis.contracts import PrehistorySpec

history = PrehistorySpec(
    kind="point_initial_value",
    lower_terminal=0.0,
    metadata={"initial_condition_kind": "classical"},
)
```

## `TrajectoryInput`

The object copies samples into C-contiguous read-only `float64` arrays and
validates strictly increasing times, aligned shapes, finite values, projection
labels, and semantic tokens. Fractional inputs require all of the following:

- `derivative_definition`;
- a scalar, vector, or structured `order` record;
- `memory_policy`;
- a non-`not_applicable` `PrehistorySpec`.

```python
import numpy as np

from hidden_attractors.analysis.contracts import PrehistorySpec, TrajectoryInput

t = np.linspace(0.0, 20.0, 20_001)
x = np.column_stack((np.sin(t), np.cos(t)))

trajectory = TrajectoryInput(
    t=t,
    x=x,
    system_kind="fractional_continuous",
    derivative_definition="caputo",
    order=(0.90, 0.90),
    projection=("position", "velocity"),
    memory_policy="full_history",
    lower_terminal_and_prehistory=PrehistorySpec(
        kind="point_initial_value",
        lower_terminal=0.0,
    ),
    solver_and_tolerances={
        "method": "abm_pece",
        "step": 0.001,
        "corrector_iterations": 1,
    },
)
```

`trajectory.fingerprint()` hashes the sample arrays and all semantic metadata.
Changing the projection, solver, order, history, or memory policy therefore
changes the SHA-256 even if the raw state matrix is unchanged.

For a public `SimulationResult`, use the non-mutating adapter:

```python
trajectory = TrajectoryInput.from_simulation_result(
    simulation_result,
    projection=("x", "y", "z"),
    transient_interval=(0.0, 100.0),
)
```

The adapter keeps `SimulationResult.times` as the analysis time axis. For a
Caputo--Hadamard or conformable solver it also preserves the integration-clock
samples under `solver_and_tolerances["integration_coordinate_times"]`, together
with the named grid coordinate.

## `AnalysisResult`

`AnalysisResult` is a backend-neutral envelope with:

- a canonical method name;
- immutable values and parameters;
- backend (`hafo_python`, `hafo_numba`, `hafo_c`, `julia`, or `external`);
- package versions and build hashes;
- evidence status and scope;
- warnings and references;
- the source trajectory SHA-256.

```python
from hidden_attractors.analysis.contracts import AnalysisResult

result = AnalysisResult(
    method="example_finite_diagnostic",
    values={"value": 0.42},
    parameters={"window": 1000},
    backend="hafo_numba",
    status="finite_numerical_diagnostic",
    trajectory_fingerprint=trajectory.fingerprint(),
    warnings=("This value is not a chaos or hiddenness certificate.",),
    references=("10.0000/example",),
)
```

`to_serializable()` returns detached JSON-compatible data. A result marked
`validated_reference` records a validation role; it does not promote a finite
trajectory calculation into an analytic theorem or a global attractor claim.

## Scientific boundary for fractional data

A finite vector of fractional coordinates is generally not the complete
hereditary state. Trajectory-based diagnostics can be applied to it, but the
result describes the supplied projection under the recorded history and memory
policy. Two visually identical coordinate traces with different lower
terminals, prehistories, or memory approximations are not automatically the
same dynamical experiment.
